# Web Design Process (Wireframe → Hi-Fi → Refinements)

## Overview
3-phase web design process. AM must complete Discovery Brief before Phase 1 begins.

**Discovery (AM prerequisite):** Brand materials, 3–5 site inspirations, page goals/structure, functional needs. If missing → do NOT start Phase 1.

## Phase 1 — Wireframe (Structure & Layout Only)
**Deliverable:** Low-fidelity black-and-white wireframe in Figma.
- Includes: 1 homepage wireframe (shared with client) + 1 internal page wireframe (internal only, shared with Content team)
- No color, images, patterns, shadows, or effects — pure structure
- Label each block (e.g., "Hero," "Trust Section," "Services Grid")
- Designer provides written Design Rationale (3–6 bullets, plain language) alongside wireframe
- Client provides ONE consolidated round of feedback then approves
- After approval: structural changes are locked (minor tweaks in Phase 2 only)
- No revisions within the phase — wait for consolidated AM feedback

## Phase 2 — High-Fidelity Design (Full Visual Design)
**Deliverable:** Fully designed, brand-aligned layout in Figma following approved wireframe exactly.
- Apply branding: typography, color palette, imagery, graphics
- Do NOT alter structure unless AM approves a minor layout tweak
- Ensure accessibility standards (contrast, legibility)
- Client provides ONE consolidated round of visual feedback
- Major layout changes = new scope

## Phase 3 — Final Design Refinement (Polish Only)
**Deliverable:** One round of small refinements + final design handoff package for Web Team.
- Minor updates only: spacing, color tweaks, image swaps, typography refinements
- Prepare organized layers + components for developer handoff
- Package assets: typography, imagery, iconography, design system elements

## Revision Scope
**In scope:** Spacing, color adjustments, content swaps, typography refinements, minor repositioning
**Out of scope:** New layouts after Phase 1 approval, redesigning pages in multiple styles, adding new pages/modules, changing brand direction mid-project

## Web Maintenance (CMS/Webflow)
For simple CMS tasks (updating bulletins, CMS items, livestream links):
- Log into Webflow → find site → CMS → update/add item → publish CMS first → publish site → verify live → mark complete in Basecamp and assign to AM for QA

For component edits in Webflow:
- Design workspace → Navigator → hover section → Edit Main Component → make changes → Publish

**Always:** Publish CMS before publishing site. Verify live before marking task complete.
