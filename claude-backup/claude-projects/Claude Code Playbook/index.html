Chapter 01

What Is Claude Code?

A developer that lives in your terminal — one that reads your files, writes code, and never gets frustrated.

Claude Code is an AI assistant that runs inside your Mac terminal (the black window with text). Unlike Claude.ai in a browser, Claude Code can read and edit actual files on your computer, run commands, and remember your entire project across conversations.


Think of it as a senior developer sitting next to you — one that works at the speed of thought.

Chapter 02

Installing Claude Code on a Mac

Two things to install: Node.js, then Claude Code. Takes about five minutes.

Step 1 — Check for Node.js

Open Terminal and type:

node --version

If you see a number like v20.11.0, you already have it. If not, go to nodejs.org, download the LTS version, and install it like any Mac app.

Step 2 — Install Claude Code

In Terminal, run this command:

npm install -g @anthropic-ai/claude-code

The -g flag installs it for your whole computer, not just one folder.

Step 3 — Connect your account

Option A — Claude Pro ($20/mo, recommended for beginners):

claude # A browser window will open — sign in with your Claude account

Option B — API Key (pay per use):

export ANTHROPIC_API_KEY="sk-ant-your-key-here" claude
!

This didn't work — I got an error running npm install

The most common cause is Node.js not being installed correctly, or a permission error. Don't try to fix it by guessing — screenshot the error instead.

What to screenshot & share

  • The full terminal window showing the command you typed and the error message
  • Share it and say: "I ran npm install -g @anthropic-ai/claude-code and got this error. What's wrong and how do I fix it?"

Chapter 03

Setting Up Your Terminal

So that opening any new Terminal window and typing claude is all it takes.

Make claude work everywhere

Run these two commands in Terminal:

echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.zshrc source ~/.zshrc

Then test it:

claude --version

If you see a version number, you're done. Every new Terminal window will now recognize the claude command.

Pro tip: Always navigate into your project folder before starting Claude. Use cd ~/Desktop/My\ Project then claude. This gives Claude full context of your files from the start.

Chapter 04

How to Start a Project the Right Way

The more context you give Claude upfront, the fewer corrections you'll make later. Start with a brief.

The Project Brief

Before asking Claude to write any code, send it a message like this:

"I want to build a web app. Here is everything you need to know:

What it does: [describe the purpose in plain English]
Who uses it: [who will log in or view it]
Key features: [list 3–5 things it needs to do]
What I do NOT want: [unnecessary complexity, logins, etc.]
Where it will live: [a website, a server, my computer only]

Before writing any code — ask me any clarifying questions you have."

Why this works

Claude will ask smart follow-up questions instead of making assumptions. Every unchecked assumption becomes a bug you'll need to fix later. Richard's opening brief for his email signature app meant Claude never suggested a complex framework — it stayed in scope from day one.

Chapter 05

How to Communicate Without Knowing Code

You don't need technical vocabulary. Describe behavior — what you see, what you expected, what happened instead.

The formula

"When I [do this action], I expected [this to happen], but instead [this happened]."

Instead of saying…Say this instead
The API endpoint is returning a 500When I click Save, I get a red error and nothing saves
The CSS flexbox alignment is offThe photo is showing up on the wrong side — it should be on the left
The session token isn't persistingEvery time I refresh the page, I get logged out
The SQL query isn't filteringWhen I search for a name, it shows all employees instead of just that one
Golden rule: If you can take a screenshot of the problem, do it. A screenshot is worth a thousand technical words.
!

This didn't work — Claude keeps misunderstanding what I want

Try reframing: instead of describing what to build, describe the experience of using it. Walk Claude through what you would click, see, and do — step by step.

What to screenshot & share

  • A screenshot of the current state of your app
  • Share it and say: "Here is my app right now. [screenshot] I want a user to be able to [step 1], then [step 2], then [step 3]. Currently it doesn't do that. How do we get there?"

Chapter 06

Staying Organized — Storing Conversations

End every session by asking Claude to save a summary. Never lose progress again.

Ask Claude to save a memory

At the end of every work session, say:

"Please save a memory of everything we built today, all the decisions we made, the current state of the project, and what's left to do."

Claude will write .md files that it reads automatically the next time you open your project.

Your own notes folder

Also keep a manual backup. Create a folder on your Desktop:

# Example folder structure Desktop/ My Project/ ← your actual app files My Project Notes/ ← your session summaries session-2026-03-24.md decisions.md roadblocks.md
!

This didn't work — Claude doesn't seem to remember our last session

Memory files are tied to the folder you launch Claude from. If you started Claude from a different folder, it won't see the right memories.

What to screenshot & share

  • A screenshot of the folder you have open in Terminal (the path shown in the prompt)
  • Share it and say: "Claude doesn't remember our last session. I launched it from this folder [screenshot]. Where should the memory files be and how do I check if they exist?"

Chapter 07

Resuming Where You Left Off

Open a new terminal. Navigate to your project. You're back.

Three ways to resume

  1. Claude's built-in memory (automatic)
    cd into your project folder and type claude. Say:
    "Please read your memory files and give me a summary of where we left off."
  2. Your own notes file
    "Please read the file at ~/Desktop/My Project Notes/session-2026-03-25.md and use it as context. Let's continue from there."
  3. Just tell Claude what you remember
    "Last session we finished the employee list page. Today I want to add a search bar. Here's a screenshot of where we are."
!

This didn't work — Claude is starting fresh and has no context

If memory files weren't saved at the end of your last session, Claude starts blank. Your notes folder is your backup.

What to screenshot & share

  • A screenshot of your app in its current state
  • Any notes you kept manually
  • Share them and say: "Claude has no memory of our last session. Here's a screenshot of the current app and here are my notes. Can you get up to speed and tell me what state we're in?"

The cross-reference technique

When Claude Code is stuck or giving you circular answers:

  1. Screenshot the problem (what you see in the browser)
  2. Screenshot the relevant code (ask Claude: "show me the relevant file")
  3. Open ChatGPT in a browser tab
  4. Upload both screenshots and ask: "I'm building a web app and hit this problem. Here's the error and the code. What's wrong?"
  5. Bring ChatGPT's answer back to Claude Code: "ChatGPT suggested [paste]. Does that make sense? Can you try it?"
!

This didn't work — I shared a screenshot but Claude can't see it

Claude Code in the terminal accepts image attachments — drag and drop the screenshot directly into the terminal window, or reference the file path.

What to screenshot & share

  • A screenshot of the terminal and the image you're trying to share
  • Say: "I'm trying to share a screenshot with you. Here's the file path: ~/Desktop/screenshot.png — can you read it?"
  • Alternatively, open Claude.ai in a browser and share it there instead

Chapter 09

Claude Code vs. ChatGPT

These tools are complementary. Know when to use each one.

Use Claude Code (terminal) when…Use ChatGPT (browser) when…
Actually writing or changing codeDiagnosing a problem from a screenshot
Making changes to your project filesGetting a plain-English explanation
Running or deploying your appGetting a second opinion
Remembering your project across sessionsQuickly testing an idea before committing
Reading terminal error logsYou're stuck and want a fresh perspective
Mental model: Claude Code is your developer — it has its hands on your keyboard and files. ChatGPT is the consultant you call when you want a second opinion.
!

This didn't work — both Claude and ChatGPT are giving me contradictory advice

When two AIs disagree, the conflict usually reveals an ambiguity in how the problem was described. Go back to basics — describe the behavior, not the technical solution.

What to screenshot & share

  • Screenshots of both answers side-by-side
  • Share with Claude and say: "ChatGPT told me [X] and you told me [Y]. They seem to conflict. Here's the problem I was originally trying to solve: [describe]. Which approach is right for my specific situation?"

Chapter 10

How to Verify Claude's Work

You can't read the code — that's fine. Here's how you quality-check without it.

  1. Test the behavior in the browser — click through every feature that was changed. Ask: does the thing I asked for now work? Did anything that worked before now break?
  2. Ask Claude to explain what it changed
    "What files did you change and what did you do? Explain it like I'm not a developer."
  3. Ask Claude to verify it for you
    "Can you verify this is working correctly? What should I look for in the browser to confirm?"
  4. Trust your eyes — you are the product manager. If the app looks and behaves the way you described, the code is probably right.
!

This didn't work — something else broke after Claude made changes

This is called a regression — a fix that breaks something else. Ask Claude to undo the last change and try a different approach.

What to screenshot & share

  • A screenshot of what broke (the before state if you have it, and the after)
  • Say: "After your last change, this [screenshot] stopped working. It was working fine before. Can you identify what changed that caused this and fix it without breaking what you just built?"

Chapter 11

Questions to Ask When You Hit a Roadblock

Keep these ready. They'll get you unstuck almost every time.

When something breaks

"Something stopped working after the last change. Can you look at what we just changed and figure out why?"
"Here is a screenshot of the error. What does this mean and how do we fix it?"
"Let's undo the last change and try a different approach."

When Claude's solution isn't working

"That didn't fix it. Here's what's still happening: [describe]. What else could be causing this?"
"Can you try a completely different approach to this?"
"I asked ChatGPT and it suggested [paste suggestion]. What do you think? Can you try that?"

When you're going in circles

"Let's step back. Here is the original goal: [describe]. What's the simplest possible way to achieve this?"
"Can you summarize what the real problem is in one sentence?"
!

This didn't work — I've asked the same question five times and we're going in circles

Stop the loop. Start a fresh session with a clean description of the problem — sometimes context accumulates in a way that confuses the model.

What to screenshot & share

  • Screenshot of the app in its current broken state
  • Open a fresh terminal, new Claude session, and say: "I'm starting fresh. My app does [X]. There is one thing that's broken: [describe behavior]. Here's a screenshot. Let's solve just this one problem cleanly."

Chapter 12

Ask Claude to Explain What It Did

Build enough understanding to direct Claude — you don't need to write code, you need to know good work when you see it.

After any significant change, ask:

"Explain what you just built like I'm a smart person who doesn't know how to code. What does each piece do and why did you make those choices?"

Over time these explanations build a mental model of your app. You'll understand the architecture — and that's enough to direct Claude effectively.

What to do with the explanation: Save it to your notes folder. If something doesn't sound right, say so: "That doesn't match what I expected. I thought [your expectation]. Which one of us is right?"
!

This didn't work — Claude's explanation is still too technical

Push back directly. Claude will always simplify further if you ask.

What to screenshot & share

  • No screenshot needed for this one — just say:
  • "That explanation is still too technical. Explain it like you're talking to a business owner who has never written code, using only analogies to things I'd experience in everyday life."

Basic Git — Saving & Deploying Your Work

Three commands. That's all you need to save and ship your code.

The three commands

git add . git commit -m "describe what you just built" git push

CommandWhat it does
git add .Stage all changed files ("I want to save these")
git commit -m "..."Save a labeled snapshot
git pushSend that snapshot to GitHub

Chapter 14

The Memory System

Claude Code stores notes about your project in text files so it remembers decisions, not just code.

How it works

Claude writes .md memory files linked to your project folder. The next time you open Claude in that folder, it reads them automatically.


What to ask Claude to save

"Please save a memory of everything we built today, all major decisions and why we made them, the current state of the project, and any known issues or next steps."

What makes a good memory file

  • Project state — what exists, what doesn't yet
  • Decisions and why — "We chose SQLite because it's simpler for a single server"
  • Known issues — things you know are incomplete
  • Next steps — what you planned to tackle next
!

This didn't work — Claude saved a memory file I can't find

Memory files are usually saved inside a hidden .claude folder linked to your project. You can ask Claude directly where it saved them.

What to screenshot & share

  • No screenshot needed — just ask Claude: "Where did you save the memory files for this project? Can you list the file paths?"
  • If you want a backup, say: "Can you paste the full contents of the memory file into this chat so I can copy it to my notes folder?"
